# age

Streaming encryption and decryption in the [age v1 file format](https://c2sp.org/age), to X25519 recipients (`age1…`): files that `age` and `rage` read, and that this crate reads from them. Sootmark's collector encrypts triage archives to a case's key with it; the workbench decrypts them. The format is written here; the cryptography is RustCrypto's (`chacha20poly1305`, `hkdf`, `hmac`, `sha2`) and dalek's (`x25519-dalek`).

```toml
[dependencies]
sootmark-age = "0.1"
```

```rust
let recipient: age::Recipient = "age1…".parse()?;
let mut encryptor = age::Encryptor::new(File::create("triage.zip.age")?, &[recipient])?;
io::copy(&mut File::open("triage.zip")?, &mut encryptor)?;
encryptor.finish()?;

let identities = age::parse_identities(&fs::read_to_string("case-key.txt")?)?;
let mut plaintext = age::decrypt(File::open("triage.zip.age")?, &identities)?;
io::copy(&mut plaintext, &mut File::create("triage.zip")?)?;
```

## What you get

- `Encryptor::new(writer, recipients)`: writes the header (a fresh 128-bit file key wrapped for each recipient, under a fresh ephemeral key, and the header MAC), then encrypts whatever is written to it in 64 KiB chunks. Memory use is one chunk whatever the size. `finish()` writes the final chunk; a file without it reads as truncated.
- `decrypt(reader, identities)`: reads the header strictly (LF line ends, arguments of visible ASCII, bodies wrapped at 64 columns, canonical base64 everywhere, at most 1 MiB), opens the X25519 stanza addressed to one of the identities, checks the MAC, and returns a `Decryptor` that reads the plaintext. Errors: `MalformedHeader`, `NoMatchingIdentity`, `HeaderMac`, `Io`.
- `Decryptor` releases a chunk only once its tag checks. A damaged or tampered chunk, an empty final chunk or data after the final chunk is an `InvalidData` error; a file cut at a chunk boundary is `UnexpectedEof`. Every later read fails again, so an error can't be mistaken for the end.
- `Recipient` (`age1…`) and `Identity` (`AGE-SECRET-KEY-1…`) with Bech32 read and written; `Identity::generate()`, `to_public()`, and `parse_identities` for files as `age-keygen` writes them (`#` comments skipped). Secret keys are wiped when dropped and never shown by `Debug`.
- Hostile input is an error, never a panic, and no `unsafe`.

Not supported: passphrase (scrypt), post-quantum and plugin recipients, whose stanzas are skipped when decrypting; the ASCII-armored form; seeking.

## How it's checked

- C2SP's age test vectors (CCTV, 0BSD, `tests/fixtures/cctv/`): every one this crate can run (69 of 147; the others are armored, passphrase-only or post-quantum-only) ends as expected: success, no match, HMAC failure, header failure or payload failure, with the plaintext released before any failure hashing as expected.
- Files encrypted by the reference Go `age` (`tests/fixtures/age/`, regenerated by `scripts/fixtures.sh`) decrypt here. In CI, `scripts/interop.sh` goes both ways with `age` and `age-keygen`: around every chunk boundary, several recipients, 100 MB, and damaged files of ours refused by `age`.
- Round trips at every chunk boundary, writes of any size, several recipients, the wrong identity, files cut short or extended, the specification's example keys, BIP 173's Bech32 vectors and RFC 4648's base64 vectors.
- Property tests: arbitrary bytes, as a file, as header lines or after a valid header, never panic; every single-bit flip and every truncation of a small file, and any byte changed in a two-chunk file, fail, and the plaintext released before the failure is genuine.
